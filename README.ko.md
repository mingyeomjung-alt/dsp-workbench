# DSP Workbench

**실험적 시제품 체크포인트 · 2026-10-17.** 나중에 개발을 재개할 수 있도록 소유자 비공개 저장소에 보존합니다. 사용자 판단에 따라 고객 인터뷰·접촉·외부 시험은 보류하며, 상용 출시가 아닙니다. [현재 상태·복원·재개 안내](docs/CHECKPOINT.md)에 검토한 동결 엔진 소스·테스트 보관본을 정리했습니다.

**오디오 처리 후 소리가 잘리거나 반복된 위치를 찾는 개발자용 진단 도구입니다.**

원본 WAV와 처리본을 비교해 의심 구간을 확인하고 해당 위치를 들어볼 수 있습니다. 코드를 변경했다면 같은 원본의 기존 출력과 새 출력을 묶어 회귀 검사할 수 있습니다.

## 할 수 있는 일

- 원본·처리본 한 쌍 비교, 또는 최대 **6사례 회귀 검사**
- 시간 대응 관계 추정과 지원 범위 내 누락·인접 반복 후보 표시
- 후보 위치와 대응 구간 청취
- JSON 근거와 단독 열람 가능한 HTML 보고서 저장
- 오디오 분석 API로 파일을 보내지 않고 **고정된 0.1.20 Python DSP 엔진을 브라우저 Worker에서 실행**

전체 음질 평가, 음성 인식·인증, 잡음 제거, 배포 자동 승인 도구가 아닙니다. 신호 차이를 진단하며, 의도한 편집인지 버그인지는 사용자가 확인합니다.

## 예제로 시작하기

**Node.js 20 이상**, 최신 데스크톱 브라우저, 실행 환경 다운로드를 위한 인터넷 연결이 필요합니다. `npm install`은 필요 없습니다.

```sh
npm start
```

터미널에 표시된 로컬 주소를 여세요. `web/index.html`을 더블클릭해서 열면 실행 환경을 불러올 수 없으므로 HTTP 주소를 사용합니다.

1. **예시 파일로 시작**을 누릅니다.
2. **비교 검사 시작**을 누릅니다.
3. 후보 위치를 듣고 JSON 또는 HTML을 저장합니다.

자체 합성 예제는 **2.0–2.1초의 100 ms 누락**을 포함하며 이에 맞는 `v11` 모드를 선택합니다. **구간 검토 필요**가 나오는 것이 예제의 정상 동작이며 실패가 아닙니다. 이 예제가 실제 현장 정확도를 증명하지는 않습니다. 일반 기본값은 여전히 `v1`이고, 고급 모드는 화면에 표시된 처리 조건에만 사용합니다.

기존·새 출력을 검사하려면 **회귀 검사**에서 원본·기준 출력·새 출력을 넣고 버전 이름을 입력하세요. 이름을 적었다고 해당 빌드나 기준 출력이 검증·승인되는 것은 아닙니다.

처음 사용하는 환경에서는 [첫 사용 점검표](docs/FIRST_TRIAL.md)로 실행·재생·저장 여부를 짧게 기록할 수 있습니다. 실제 처리 파일이 없다면 예제 점검까지만 진행하면 됩니다.

## 입력 범위와 결과 읽기

| 항목 | 현재 웹 입력 한도 |
| --- | --- |
| 형식 | PCM16 모노 WAV |
| 길이 | 파일당 2–30초 |
| 샘플률 | 8 / 16 / 44.1 / 48 kHz |
| 파일 크기 | 파일당 최대 10,000,000바이트 |
| 일괄 검사 | 최대 6사례, 전체 입력 합계 64 MiB |

반드시 **같은 원본에서 나온 파일**을 비교하세요. 서로 따로 녹음한 두 음성, MP3·M4A, 다채널·장시간 녹음은 이 화면의 지원 대상이 아닙니다. 파일을 자동 변환하지 않습니다. 실제 수행한 음량·리샘플링 처리만 표시하고, 고급 모드의 좁은 지원 조건을 확인하세요.

- **시간적 후보 없음**: 지원 범위에서 후보를 관측하지 못했다는 뜻입니다. 전체 음질 승인이 아닙니다.
- **구간 검토 필요**: 해당 위치를 듣고 의도한 편집인지 결함인지 확인해야 합니다.
- **판단 보류 / 버전 간 비교 불가**: 근거가 부족한 상태이며 통과가 아닙니다.
- 회귀 검사의 **신규·유지·이번 미관측**은 두 결과에서 관측한 후보의 관계입니다. 이번에 보이지 않았다고 이전 결함의 해결을 확정하지 않습니다.

## 파일과 실행 환경

선택한 오디오는 브라우저의 임시 메모리에서 처리하며 로컬 미리보기 서버·외부 분석 서비스에 전송하거나 브라우저 저장소에 보관하지 않습니다. 내려받은 보고서에는 진단 정보와 파일 해시가 포함되므로 공유 전 내용을 확인하세요.

첫 분석 시 CDN에서 **Pyodide 0.29.3**, NumPy·SciPy와 프로젝트의 고정 엔진 파일을 내려받습니다. 외부 제공자는 일반적인 실행 파일 요청을 수신하고, 브라우저 캐시에 실행 파일이 남을 수 있습니다. **오프라인 배포본은 아닙니다.** 메모리 부족, 브라우저 제한, 다운로드 실패가 발생하면 분석이 불가능할 수 있으며 이를 정상 판정으로 취급하지 않습니다.

**64 MiB는 입력 파일 합계 한도이며 RAM 사용량 상한이 아닙니다.** 수치 계산과 임시 사본에는 추가 메모리가 필요합니다. 데스크톱에서 짧은 파일 한 사례부터 시작하고, 무거운 일괄 검사는 나누어 실행하세요. 준비가 실패하면 다시 실행할 수 있으며, 취소하면 실행 Worker를 종료하고 이전 작업 결과를 폐기합니다. 준비 제한 시간은 4분, 분석 제한 시간은 10분입니다. 이 시간은 응답 속도 약속이 아니라 멈춘 작업을 종료하기 위한 한도입니다. [검증 범위와 한계](docs/VERIFICATION.md)를 참고하세요.

Node 서버는 현재 PC의 로컬 접속용이며 **계정 로그인 기능은 없습니다.** 고객용 호스팅이나 외부 공개 운영 서버가 아닙니다. 정적 호스팅은 가능하지만 GitHub Pages 배포는 설정하지 않았습니다. **비공개 GitHub 저장소라고 Pages 사이트도 자동으로 비공개가 되는 것은 아닙니다.** 브라우저 실행 시 허용된 수신자에게 엔진 wheel도 전달되므로, 이 방식이 해당 수신자에게 엔진 코드를 숨겨 주지는 않습니다.

## 동작 점검

```sh
npm test
```

포함된 Node 계약·WAV 구조·취소/재시도 상태 검사를 실행합니다. 상태 검사는 모의 브라우저 객체를 사용하므로 실제 브라우저 호환성 시험을 대신하지 않습니다. 검사 통과는 실제 탐지 정확도를 뜻하지 않습니다. 선택적으로 네이티브 엔진을 확인할 수 있습니다.

```sh
python scripts/check_engine.py
```

이 명령은 Python 3.12와 호환 NumPy·SciPy가 설치된 환경에서 사용합니다. 포함된 고정 엔진 wheel을 직접 읽으므로 엔진을 별도로 설치할 필요는 없습니다. 의존성 자동 설치나 오디오 업로드는 하지 않습니다.
